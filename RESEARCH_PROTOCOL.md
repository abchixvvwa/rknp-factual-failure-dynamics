после заранее документированного решения. Каждый основной факт требует human verification.

состав категорий требуется проверить перед freeze. Существующие отличающиеся splits не перезаписываются.

## Возобновление и бюджет
Перед отправкой фиксируется резерв бюджета в SQLite (WAL, synchronous=FULL); после ответа
ответ и usage сохраняются транзакционно. Резерв учитывает вход в UTF-8 байтах с запасом и
максимальный выход; это консервативная оценка, а не точный токенизатор. Неизвестный usage не
превращается в ноль. Все попытки, включая 429 и ошибки, учитываются. Локальный день — UTC.
Заголовки Groq requests относятся к RPD, tokens — к TPM; Retry-After не сокращается.
Для одного журнала допускается один активный writer. Сохранённый успешный request key пропускается.
Зависший in-flight запрос требует осмотра и явного --retry-uncertain. Обеспечивается уникальность
локальных успешных записей, но не exactly-once на сервере: при потере соединения сервер мог выполнить
запрос. Timeout retries сохраняют эту неопределённость в журнале. Ключ API не записывается в артефакты.
Parquet обновляется на контрольных точках и при выходе; после аварийного завершения его можно
восстановить из журнала. Изменение научных входов требует нового experiment_id.

## Формулы признаков, feature version semantic_dynamics_v1

На каждом k=2,3,4,5 считаются независимые semantic groups только по видимому префиксу.
Финальная группировка пяти samples не используется для ранних k. Сначала применяются точные
нормализованные, числовые и календарные сопоставления; неоднозначности передаются fixed judge.
Высокая похожесть RapidFuzz сама по себе не доказывает semantic equivalence и используется как baseline.
Judge для grouping видит только вопрос и текущие samples; target support проверяется отдельно без ground truth.
Максимум дополнительных judge-вызовов — 8 на case (4 grouping + 4 target support), обычно меньше
благодаря детерминированным правилам и кэшу. Этот расход учитывается отдельно от 1+5 генераций.

При размерах кластеров n_i, числе samples k и p_i=n_i/k:
H=-Σp_i ln(p_i); H_norm=H/ln(k). Disagreement=1-max(p_i). Consensus margin — разность
двух наибольших долей (вторая равна 0 при одном кластере). Target support — число эквивалентных
target samples, делённое на k; это не factual correctness. Непонятное judge-решение не превращается в ноль.
При равных размерах dominant выбирается по самому раннему sample index. Идентичность dominant
для switching определяется самым ранним членом, а не произвольным номером, возвращённым judge.

Entropy slope — коэффициент линейной регрессии H_k по k, AUC — трапецеидальный интеграл по k;
last delta=H_5-H_4; max delta=max(H_3-H_2,H_4-H_3,H_5-H_4); variance — population variance.
Cluster births — сумма положительных приростов числа кластеров между k=2→3→4→5.
Dominant/target-support slopes определяются такой же линейной регрессией; min и final — минимум и
последнее значение соответствующей траектории. Switch count — число изменений dominant identity.
Late disagreement=1, если n_clusters_5>n_clusters_4. Stabilization — самый ранний наблюдаемый k,
после которого dominant не меняется и каждый следующий |ΔH_norm|<epsilon; если такого раннего k нет,
получается 5. Для smoke epsilon=0.05 — временное инженерное значение; научный epsilon выбирается
только на validation и фиксируется до test. В adaptive расчёт ограничивается текущим k.

Lexical diversity — число уникальных нормализованных ответов / k; pairwise Jaccard считается по
множествам токенов, RapidFuzz ratio делится на 100. Каждый feature row ссылается на case_id,
target request/hash, benchmark/split/label/grouping hashes. Unresolved factual labels остаются пустыми.

Версии semantic_v1/v2 сохранены отдельно после ошибок формата. semantic_v3_prefix использует
строгую JSON Schema с обязательной меткой каждого видимого ответа и прямой JSON без tool wrappers.
Это обеспечивает проверяемый формат, но не смысловую правильность. Отдельный quality report считает,
сколько раз judge менял отношения между уже виденными парами при добавлении следующего sample.
Эти изменения не скрываются и не являются основанием для недокументированного исключения случаев.
При обрыве judge на 256 токенах допускается один повтор с потолком 1024 и теми же входами/seed/model.
Оригинальный ответ, отдельный retry request_id, фактический потолок и ссылка на обрыв сохраняются.
Для engineering допускаются оба потолка; научный freeze должен явно включать эту политику восстановления.

Текущие десять smoke-фактов уже использованы при инженерной настройке; их нельзя впоследствии
включать в нетронутый main test. Планирование научного pilot/main должно учитывать этот факт.

Автоматические маркеры отказов в data-quality report служат только для поиска ответов на проверку.
Они не превращаются автоматически в factual error labels. До научного pilot требуется явно закрепить
правило для воздержаний от ответа; пока неуверенные случаи имеют статус unresolved.

## Реализация обучения и выбора на validation — 2026-09-11

B0 использует prior по train. B1=(unique_normalized_answers−1)/4; B2=1−mean(mean Jaccard, mean RapidFuzz ratio);
B3=H_5/ln(5); B5=1−target_support_ratio. Это фиксированные risk scores, а не заранее калиброванные вероятности.
B4 — StandardScaler + LogisticRegression(C=1, max_iter=2000) на STATIC_FEATURES.
Dynamic использует STATIC_FEATURES + SUPPORT_FEATURES + DYNAMIC_FEATURES без идентификаторов, языковых
меток, источников, эталонных ответов и factual labels в предикторах. Сравниваются та же logistic regression,
RandomForest(300 trees, min_samples_leaf=5) и HistGradientBoosting(100 iterations, max_leaf_nodes=15,
l2=1, early_stopping=False). Все случайные процедуры используют seed=42.

Scaling обучается внутри Pipeline только на train (или train части каждого fold). Калибровочные варианты:
raw, sigmoid/Platt на logit ограниченного исходного score и isotonic. Калибраторы обучаются исключительно
на out-of-fold прогнозах train с группировкой fact_id (до пяти folds; каждый обучающий fold обязан иметь
оба класса). Все языки и модели одного факта остаются в одном fold. Полный estimator затем обучается на train.
Validation выбирает калибровку по минимальному Brier, затем порог по max F1. При равенстве Brier порядок
raw→sigmoid→isotonic; threshold tie-break закреплён в select_threshold. Proposed classifier выбирается
по validation AUROC после калибровки; tie-break — logistic→random forest→hist gradient.
Сохраняются все варианты, calibration curves, folds, hashes кода/входов/моделей и версии пакетов.

Test predictors/labels не загружаются; читаются только case_id/fact_id/split для проверки разделения фактов.
Обучение блокируется на smoke (<100 фактов с признаками), неразмеченных train/validation случаях и отсутствии
одного из классов. Минимум 100 feature-bearing facts — консервативная проверка текущей реализации; исключения
с отсутствующими признаками могут потребовать добора фактов, а не изменения порога после просмотра результатов.
Артефакты и selection.json не перезаписываются. Эти настройки — подготовка к pilot, не main freeze.
Научное обучение пока не выполнялось; unit-тесты на искусственных fixtures не являются результатами исследования.
